# Navigation decision

## Alternatives evaluated

| Structure | Strength | Failure | Decision |
| --- | --- | --- | --- |
| Today / Trends / You | maps to daily, longitudinal, ownership jobs; calm and familiar | logging needs a visible action | Chosen; labelled Log action on Today |
| Today / History / Settings | concrete | History duplicates domains; Settings undervalues ownership/context | Rejected |
| Home / Insights / Profile | broadly familiar | “Insights” and “Profile” are vague; account connotation | Rejected |
| Now / Signals / Patterns | distinctive language | learning cost; Signals and Patterns overlap | Rejected |
| Today / Trends / Log / You | direct logging | four permanent destinations for an occasional task | Rejected after simplicity review |

## Why device is not a tab

Device mechanics should disappear when functioning normally. A compact ring icon
with battery/last-sync appears in Today's header only when useful; tapping it opens
the panel. Full device settings live under You. A permanent Device tab would give
connection mechanics equal weight with the user's health question.

## Reachability

From Today: Sleep/Recovery explanation 1 tap; weekly Trends 1 tab; Log Swim 2
taps; battery 1 tap; export 2 taps (You → Data); privacy 2 taps. Every common task
meets the three-tap target without hidden gestures or icon-only primary actions.

## Platform behaviour

Use a native-feeling bottom navigation with text labels and stable ordering. It
remains visible on top-level screens and hides on focused forms/inspect views.
Deep links target semantic routes, not tab indices. Back preserves date, scroll,
and range context.
