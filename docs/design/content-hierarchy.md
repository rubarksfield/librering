# Content hierarchy

## Today — first viewport

1. Date/greeting and compact ring status.
2. **Daily Signal:** one sentence, e.g. “A shorter night is the main reason today
   may feel less supported.” This is not a fourth score.
3. Three status summaries: Sleep, Recovery, Movement. Each shows status/score (if
   defensible), plain meaning, confidence, main reason, and one tap target.
4. One issue card only if action is needed: incomplete sync, low battery, or
   missing critical data.
5. Labelled `Log` action.

Do not show stage percentages, HRV, SpO₂, calories, streaks, promotional content,
or a carousel in the first viewport.

## Explain screen

1. Plain result and personal comparison.
2. Confidence sentence adjacent to result.
3. Main reason.
4. Positive, negative, then missing contributors; maximum four rows before “More.”
5. One conservative action.
6. `Inspect evidence` secondary action.

## Inspect screen

1. Time-series/timeline answering one stated question.
2. Exact input values and windows.
3. Source badges: Ring estimate / App-derived / Imported / You logged.
4. Baseline version/maturity, confidence components, gaps.
5. Formula version and limitation link.

## State priority

`No result` outranks a stale number. Error/recovery information outranks advice.
Low confidence appears adjacent to the result; it is never a tiny footer. Battery
appears persistently only below a useful threshold or during a device issue.

## Copy examples

- “Recovery is slightly below your recent range.”
- “Confidence is moderate because part of the pulse record is missing.”
- “Sleep stages are estimates made by the ring, not EEG measurements.”
- “Your swim was logged manually. The ring did not measure laps or underwater
  heart rate.”
- “No Sleep result: the ring captured less than 60% of the expected window.”
